# CodexとClaude Codeの連携

## 役割と引き継ぎ

二つのツールはGitの同じ変更履歴と、この指示書を使って連携する。会話履歴やアカウントを統合する設定ではない。

- Codexに修正を依頼し、Claude Codeに差分確認を依頼する使い方ができる。逆の分担もできる。
- 確認だけなら同じ作業フォルダーを読む。別々の改修を同時に進める場合はworktreeを分ける。
- 引き継ぐ内容は、目的、対象ファイル、変更内容、成功した確認、残る問題の5点とする。
- 手元で固めてから、利用者の指示でGitHubへ送る。レビューの完了を公開・PM承認・実利用効果の確認としない。

## このパソコンで使うコマンド

`scripts/start-claude.ps1` は現在のコードを起点に、Claude Code用の別worktreeを開く。同じ場所を同時に書き換えないための入口。Claudeの作業結果は別ブランチに残るため、確認してから取り込む。

`scripts/ask-claude-review.ps1 -Task '確認してほしい内容'` はClaude Codeへ読むだけのレビューを依頼する。ファイル閲覧・検索だけを有効にし、コード編集・シェル実行・MCPツールは有効にしない。結果はGit対象外の `.agent-reviews/` に保存する。Codexはその結果を読んで、必要な修正を行える。レビューを実行するとClaude側の利用枠を使う。

Claude Codeへの初回ログイン・フォルダーの信頼確認は本人が行う。パスワード・認証コードを引き継ぎ文書やスクリプトへ書かない。既存の権限確認を無効にするオプションは使わない。

## 動作確認

- 共通保存先・残席・連絡板：`node test-shared-data.cjs`
- 自動更新・通知：`node test-live-auto-sync.cjs`
- 独自ドメインの受入れ・Origin検証：`node test-frontend-origin.cjs`
- 公開用ビルド：`node scripts/build-assets.cjs`

テストや公開を始める前に、保存先と対象の環境を確認する。実募集への申込み・投稿を試験データで増やさない。
