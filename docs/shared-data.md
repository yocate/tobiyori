# 二つの公開URLで同じ申込み・残席・連絡板を使う

`SHARED_DATA_ORIGIN` を設定した入口は、アカウント、マイページ、募集、申込み、承認、連絡板、画像を指定した1つの保存先で扱います。独立したDB同士で定期的にコピーする方式ではありません。残席の承認判定も元の一つのDBが処理するため、二つの入口から同じ残り1席を別々に承認できません。

2026年11月23日、利用者は旧サイトのデータを共通で使う方式を選びました。新しい入口の画面を配信しながら、旧サイトのアカウントとデータを使います。新サイト専用のアカウントを同一メールだけで自動統合しません。切替後の新しい入口では、旧サイトのアカウントでログインし直します。ブラウザーのログインCookieはそれぞれのホスト内に限定します。

## 設定

- `APP_ORIGIN`: この入口の公開URL。
- `SHARED_DATA_ORIGIN`: 共通の保存先のHTTPSオリジン。パス、ユーザー名、クエリ、同一オリジンは不可。未設定なら従来の独立DBで動きます。
- `SHARED_DATA_ID_ALIASES`: 独立環境へコピーした際のIDを、共通の保存先にあるIDへ対応させるJSONオブジェクト。キーと値はいずれもUUID。公開済みの新しい団体・活動URLが引き続き使えるようにします。

個人のCloudflareアカウントID、移行先の具体的なID、認証情報はこのリポジトリへ保存しません。個人用Wrangler設定は外部の作業フォルダーで管理します。`/tobiyori-shared-entry.js` はWorkerが先に処理するアセットに含めます。

## 切替前の確認と保存

入口の独立DBに、未対応の実在団体・活動や、実募集への申込み・連絡板投稿があれば切替を止めます。それらを無視して旧サイトへ切り替えません。すでに移行用に作成した団体・活動のみで、実募集への新しい申込み・投稿がない場合に切り替えられます。既知の動作確認用団体は実績と分けます。

切替前に、独立DBの一意なスナップショットを既存の非公開R2バックアップバケットの `shared-data/` に保存します。セッションと認証フローは含めません。アカウント等を含むバックアップは公開しません。保存が成功しない場合も切替を止めます。切替後の古いWorkerから独立DBへの書込みは拒否し、再読み込みを案内します。

データを変更するHTTP要求は、元の入口と同じOriginであることを確認した後に共通保存先へ送ります。アプリのセッション以外のCookie、Authorization、内部認証用ヘッダーは転送しません。Cookieの有効性、本人のID、操作権限、参加承認、定員、連絡板の閲覧権限は共通保存先が検証します。転送先のリダイレクトを追わず、失敗した投稿を自動再送しません。接続失敗時に独立DBへ保存する処理もありません。

## 確認

```sh
node test-shared-data.cjs
node scripts/build-assets.cjs
```

テストではローカルの2つの入口から同じアカウント・団体・募集を使い、両側の申込みが同じ担当者へ届くこと、最後の1席の同時承認で片方だけ成功すること、取消後の承認、双方向の連絡板、未承認者の拒否を確認します。CSRF、Cookie、内部ヘッダー、移行ID、バックアップと切替拒否も確認します。本番の実募集へテスト申込みはしません。

保存内容は即座に共通になります。画面上の表示は既存の更新操作と定期取得に従います。連絡板に常時接続の即時配信を追加した意味ではありません。

## 元へ戻す場合

`SHARED_DATA_ORIGIN` と `SHARED_DATA_ID_ALIASES` を外して新しい版を公開すると、入口は元の独立DBへ戻ります。切替中に共通保存先へ記録された申込みや投稿は、独立DBへ自動でコピーされません。運用中の切戻し前には移行・停止の手順を確認してください。共通保存先のDBや旧サイトの公開設定は、この切替では変更しません。

接続先の管理、障害、機能と運営権限は引き続き共通保存先側に依存します。将来新環境を正本にする場合は、既存アカウント・申込み・連絡履歴の移行と両側の切替を別途行います。
