# 開いた画面への自動反映

## 動作

利用者と運営者の画面で、公開された団体・活動、申込者、承認状態、残席、お知らせを自動取得し、変更時に表示を更新する。活動の連絡板は、開いたまま新しい投稿を取得する。手動の更新ボタンも残す。

Cloudflareの共通保存先が `/api/health` で `liveUpdates:true` を返す場合、`/api/live/updates` のWebSocketで変更を通知する。通知本文は `invalidate` または `auth-changed` の種別だけで、投稿本文・氏名・アカウントIDは含めない。実データは既存の認証APIで取得する。私的な変更は操作した人と通知対象者へ、公開情報の変更は全接続へ知らせる。

即時通知を利用できない保存先では、表示中の画面が約2秒間隔で確認する。通知接続中も30秒間隔で再確認する。回線状況・サーバー制限により反映に時間がかかることがある。非表示のタブは取得を控え、タブへ戻る・再接続する時に確認する。常に全端末へ同時刻に反映する保証ではない。

## 入力の保持

- 連絡板では投稿一覧だけを書き換え、未送信の文章とフォーカスを保持する。
- 全体の描画が必要な時は、編集したフォームの実際のDOM要素を再利用し、ファイル選択も保持する。
- 画面のスクロール・展開した説明・地図の位置を保つ。
- アカウントや画面が変わった後の古い取得結果は描画しない。ログイン失効時は非公開の表示を消す。
- 投稿の自動再送はしない。取得失敗時は間隔を延ばし、Retry-Afterを尊重する。

## 新旧サイトへの反映条件

新サイトは引き続き旧サイトを共通の保存先として使う。新サイトだけにこの変更を公開しても、旧サイトの配信コードは変わらない。共通保存先のWorkerへも変更を公開した後、WebSocketの即時通知を利用できる。それまでは新サイトの約2秒間隔の取得を使う。

旧サイトの管理者が、この変更を含むソースを確認し、従来の設定・保存先を保持して公開する。`SHARED_DATA_ORIGIN` を旧サイト自身に設定してはならない。氏家さんの個人用設定を旧サイトへ転用しない。既存のCloudflare公開手順は `docs/cloudflare.md` を参照する。

すでに読み込み済みの古い画面には新しいJavaScriptは注入されない。公開後に一度再読み込みする必要がある。その後のデータ変更は更新ボタンを押さずに確認できる。

## 確認

`node test-live-auto-sync.cjs` で通知・代替取得・再接続・古い結果の抑止と、対象者だけへの通知を確認する。`node test-shared-data.cjs` は共有保存先・残席競合・連絡板の権限を確認する。Cloudflare実行環境とブラウザーでの検証結果は、公開環境の結果と分けて作業記録へ残す。
